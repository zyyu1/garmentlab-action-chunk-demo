# 质量单变量对照

两组新进程串行运行：baseline 每粒子 0.01 kg（总约 99.45 kg），light 每粒子 0.0001 kg（总约 0.9945 kg）。后者是敏感性诊断点，不是测量或校准得到的真实衣物质量。

运行入口 run-mass-pair.sh，启动前按 mass-pair-files.json 校验上传版本。需要同时上传 day4-mass-sensitivity-test.py、mass_experiment.py、compare_mass_pair.py、run-mass-pair.sh、mass-pair-files.json。此前服务器已有的四份观察器和 measured_hold_step_observer.py 继续使用，入口核对其源码哈希。

mass_experiment.py 核对 v2 参数审计中记录的项目/SDK 源码和衣物资产哈希，然后仅在当前进程 Garment 模块的 ClothPrim 构造入口显式传入 particle_mass。原 SDK、项目文件不修改；backend.start 返回或异常时恢复构造入口。保留构造完成、reset 之前的 mesh 和已存在的弹簧数组。两组运行完成后比较这些数组及源码完全一致。

启动后、动作前和释放后从已初始化且 timeline 播放中的 cloth physics view 读取逐粒子质量，保存原始 NPY；要求形状 1×9945，且质量与请求一致。读取 USD 的构造质量、舞台 kg/m 单位、时间步、粒子系统迭代与接触参数。

沿用已通过的分层下降、points1 对齐、抬升、实测末端位置目标保持 180 步和释放。基线必须复现旧抬升前缀及完整 measured-hold 轨迹。light 只记录与旧轨迹的差异，不要求相同帧数/动作实际步数。原来的开启跳变、区域距离、抬升/释放检查不放宽；失败停止后续流程，保留日志与已保存结果。

结果目录为 /root/autodl-tmp/day4-mass-pair-随机后缀，其中包含两个运行子目录、日志与 comparison.json，下载整个父目录即可。最终成功标记 MASS_PAIR_COMPARISON_OK。

比较报告包含构造网格/弹簧一致性、落地状态差异、实际抬升高度、锚点索引、开启响应、边长比、最坏边、保持运动/几何间距与释放。质量改变会影响落地和自适应动作目标，因此这是相同控制策略的质量敏感性对照，不是严格相同抬升前状态的隔离实验。成功也不证明真实材料质量或全部物理正确。

本地检查：Python 3.10 语法（含 runner 内嵌 Python）、分支检查位置、离线构造包装测试通过。包装测试用替代对象验证两种质量传参、刚度参数保留与重复质量参数拒绝，未执行 Isaac/GPU 物理验证。

## 首次基线读回失败后的修订

day4-mass-pair-2Wpkom8o 的基线在动作前停止。原始读回为 1×9945 float32，全部有限、正值且均匀为 0.010000912472605705 kg，总和 99.45907454006374 kg；构造时 USD mass 为 99.44999694824219 kg。相对于请求的 0.01 kg，逐粒子误差约 0.0091247%，超过原 0.001% 数值比较容差。偏差的内部来源未确认，不将其直接归因为浮点舍入。

改用显式 0.1% 质量读回容差，并保存实际值和误差；形状、有限性、正值、均匀性继续检查。两组逐粒子读回比例额外要求接近 0.01（相对容差 0.2%，覆盖两侧数值偏差）。原物理验收及基线完整轨迹复现要求不变。用真实失败数组回归通过；错误质量、形状、非有限值、零质量和非均匀数组均被拒绝。上传哈希清单已更新，需连同两个修改后的 Python 文件重新上传。此次失败不是完成的质量对照，轻质量组未运行。
